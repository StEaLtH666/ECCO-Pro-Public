# Advanced / Experimental Configuration card - read-only inventory

Audit of worktree `(private scratch path removed)` at public main `fbe03aa` (clean). Read-only; no
repo file modified, no network / HA / dongle access. Card added by `b093aa8` (PR #13, Phase 1A); placed on the dashboard by
`42baa20` (post-export entry `acfg1`).

## 1. Intended functionality and current behaviour

**What it is.** `custom:ecco-advanced-config-card` (card version `0.1.0`, `frontend/ecco-advanced-config-card/`), a searchable,
filterable catalogue of all 165 capability-registry records in nine sections, plus a dedicated **Global Power / Export Limit
(register 245)** panel at the top. Each row: name, live value, register, status, evidence code, danger class, freshness; expand
for register / raw / decoded value, status + "why it is not writable here", evidence (proof / write policy / access), danger,
options (enum / ECCO bounds / firmware ceiling - never called a hardware maximum), explanation, interactions, source entity +
firmware decode window, raw-word entity, provenance.

**Strictly read-only, by construction** (`src/ecco-advanced-config-card.ts`, `src/model.ts`, `src/render.ts`):
- `set hass()` keeps only `hass.states`; the HA object is never stored (no `this._hass =`, no `get hass`).
- Listeners: `input` and `click` only. Only four `data-action`s: `search`, `toggle-filter`, `clear-filters`, `toggle-item`; all
  local view state. Any other action is ignored. No service call, websocket, fetch, storage, timers, events.
- Config keys accepted: `title`, `entity_prefix` (default `ecco_clock_dongle`), `max_age_telemetry_s` (120),
  `max_age_configuration_s` (300), `max_age_rtc_s` (300) + Lovelace layout keys; unknown keys throw ("no hidden switch").
- Entity ids built at run time: `<domain>.<entity_prefix>_<object>` (object = HA slug of the firmware `name:`; ESPHome
  `text_sensor` -> HA `sensor`). Catalogue domains used: `sensor`, `binary_sensor`, `switch` (switches are only READ).
- Values: unknown never shown as 0 ("Entity not found in Home Assistant", "Unavailable", "Unknown", "Not exposed by an ECCO
  entity", "Unexpected value"). Freshness: Live / "Current (poll online)" (gate `binary_sensor.<prefix>_telemetry_online` /
  `_configuration_online` on and fresh) / Stale / "Freshness not verified" / "No live value". Raw word *reported* (from a firmware
  `... Raw` / `... Raw Flags` sensor, 17 records) or *derived* (exact inverse of a linear / enum / HH:MM decode), else none.

**Status presentation** (card header badge `READ ONLY`; summary "N of 165 settings shown. This page is read-only."):

| Status | Label | Count | Meaning |
|---|---|---|---|
| PROVEN | "Proven (elsewhere in ECCO)" | 41 | read_write + live_proven_write; written only by ECCO's own guarded controls, never here |
| EXPERIMENTAL | "Experimental" | 1 | read_write, not hardware-proven (`dump_to_grid_transaction`) |
| READ_ONLY | "Read only" | 100 | ECCO has no write path |
| LOCKED | "Locked" | 16 | overlay `restrict: LOCKED` (safety-critical; all D4) |
| UNSUPPORTED | "Unsupported" | 7 | live_proof_status `unknown` or write_policy `WX`; all in Experimental / Undocumented |

Evidence codes from `live_proof_status`: M3 write-proven (41), M2 read-proven (116), M1 documented (1), M0 inferred (0), MX
unknown (7). Danger D0 telemetry / D1 cost-tariff / D2 availability / D3 regulatory / D4 equipment-safety.

**Global Power panel** (`renderGlobalPower`, overlay `global_power`): title "Global Power / Export Limit", "Register 245",
`READ ONLY` badge; current value in W, raw value, unit W, read freshness, source entity `sensor.<prefix>_ecco_export_limit`,
mapping evidence "M2 read-proven (registry: live_proven_read); owner-confirmed 2026-10-08", status "Read only. This card cannot
write...", **"Hardware maximum not verified"**, **"Regulatory export allowance not recorded"**. Then a "Design preview: these
controls are disabled" block with seven future controls: Unlock and Apply (`<button disabled aria-disabled="true">`, no
data-action), Staged value (`<input type="number" disabled>`), and text-only Permitted technical range ("Unavailable: hardware
maximum not verified"), Verification status, Previous value, History. Every control `enabled: false`, reason "Disabled: Global
Power writing is not implemented in this release." A `<details>` "Why is Global Power read-only?" lists blockers, limitations
and the owner confirmation.

**Owner decisions recorded** (`registry/advanced_config_overlay.yaml`, README):
- 2026-10-08: the inverter setting labelled "Export Limit" (register 245) IS Global Power and is the intended Global Power
  control. It stays read-only in this release; `write_status: not_implemented`.
- Write blockers (4): no firmware write path for 245 (pinned write surface excludes it, safety tests forbid one); not proven on
  the ESP32-S3 (H-002), where no ECCO write feature is re-proven yet; hardware maximum not verified (`hardware_maximum_w: null`;
  firmware TOU power ceiling is a site setting, not the HW max; rated power never read); regulatory allowance not recorded
  (`regulatory_allowance_w: null`, never inferred).
- Overlay explanation: two published descriptions disagree whether 245 caps export only or combined Load+Grid output; unproven.
- `controller_note`: registry write proofs were on the classic ESP32 (H-001); on the S3 every ECCO write path is offline-only
  until re-proven.
- Section 13 of the Inverter / Advanced view; dashboard v7.19.0 "STAGED / NOT LIVE-PROVEN" (`tested_in_home_assistant` false);
  VERSION.yaml dashboard is now 7.21.0. README still says "staged and not yet exercised in Home Assistant".

**Dashboard placement** (`home-assistant/dashboards/ecco_pro.yaml` L7065-7077, view "Inverter / Advanced" L6529,
`path: ecco-inverter-advanced`): comment banner "13. ADVANCED / EXPERIMENTAL CONFIGURATION (read-only)"; a `grid` section,

resource `/local/ecco/ecco-advanced-config-card.js`, manual registration, no restart).

## 2. Every setting (165 rows)

Columns: label = registry `name` (the card shows it verbatim); register(s) decimal (`bN` = bits); datatype x scale unit from
the registry `modbus` block, then the firmware steady-poll decode the generator derived (`linear sS offO signed`, `enum`,
`hhmm`, `bit maskM`, `bit_equals`, `bit_text`, `tou_charge`, `tou_mode`, `derived` = not a plain scaling) and its window; HA
entity id with the default prefix `ecco_clock_dongle` (exact id the card reads); firmware id + `name:` + line in
`firmware/ecco_clock_dongle_stage3_4_free_power.yaml` (the `id:` line; all 158 verified adjacent to the `name:`); link source
(`registry` = registry `entity_ha_raw`, `firmware_decode` = unique steady-poll decode of the same registers, `overlay` =
`entity_links`); registry `current_access / write_policy / live_proof_status / implementation_status`; evidence code; status
derived from registry -> shown after overlay; overlay danger; overlay record keys present (empty = category defaults only).
Full `firmware_evidence`, `ha_evidence`, `safety_impact`, `write_policy_reason`, `notes` text is in
`registry/inverter_capabilities.yaml` per record id and is rendered in the card's Provenance row.

Unlinked records (no ECCO entity; card shows "Not exposed by an ECCO entity"): `esphome_diagnostic_counters_group`,
`inverter_protocol_version`, `inverter_rated_power`, `inverter_serial_number`, `remote_lock`, `signal_island_mode`,
`smartdeye_battery_charge_voltage_parity`.

Registry totals: current_access read_only 123 / read_write 42; write_policy R0 107, W1 37, W2 4, W3 10, WX 7. Note
`grid_export_policy` (244) is W3 yet PROVEN (read_write, live_proven_write): W3 does not by itself demote.

## 4. Hooks, placeholders, design notes for future write support

- No TODO / FIXME in the card, generator, overlay or tests.
- Overlay `global_power.future_controls` (7 designed descriptions): unlock (time-limited, never grants write authority by
  itself); staged_value (checked against permitted range before Apply); permitted_range (bounded by verified HW maximum AND,
  separately, the recorded regulatory allowance; unavailable until both exist); apply ("Hands the staged value to the
  controller's guarded transaction. Only the controller writes to the inverter."); verification (exact controller readback, then
  a second read after the next configuration poll); previous_value (offered only as a new staged change with the same
  confirmation); history (HA history + controller audit counters).

  integration (Home Assistant history of the source entity)"; verificationText "No write path, so there is nothing to verify."
